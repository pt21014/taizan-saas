# taizan-saas 框架设计蓝图

> 形态已拍板：`create-taizan-saas` 生成器 + `@taizan/*` npm 核心包。本仓库自带六个端，既是参考应用也是生成器模板。新 SaaS 项目由生成器产出骨架、只写业务模块，框架升级靠改版本号。老项目（xiaodian / knowledge）不回迁，仅作为来源。
>
> 输入：`docs/多租户SaaS基座-抽取评估报告.md`、两份盘点、参考清单、`D:\project\knowledge\CLAUDE.md`（8 条硬性约定全部进框架）。

## 1. 仓库目录树


**apps 职责一句话**：`api` 全部后端；`admin` 商家日常经营；`platform` 平台运营与收费；`site` 获客与自助注册；`client` C 端触达；`app-client`/`app-merchant` 原生壳与推送场景。

## 3. 基础 schema

### 3.1 数据约定（不可协商）

| 项 | 定成 |
|---|---|
| 主键 | `String @id`，**ULID，应用层生成**（`@taizan/contracts` 的 `ulid()`；`@taizan/nest-prisma` 在 create 时自动填充） |
| 字段名 | **camelCase 直用**，不做 `@map`（生成器只服务新项目，少一层映射少一处漂移） |
| 状态 | 一律 Prisma `enum`，禁止裸 Int/String |
| 金额 | 一律 `Int`，字段名以 `Cents` 结尾，**禁用 Decimal** |
| 时间 | `DateTime`，`createdAt`/`updatedAt` 必备；软删用 `deletedAt DateTime?` |
| 租户列 | `tenantId String`，**一律 NOT NULL**；需要「平台共享 + 租户私有」的，**拆成两张表**（`RolePreset` / `Role`），绝不用可空 tenantId ——xiaodian 的 `MaterialFolder` 因可空被移出隔离名单，例外最容易丢 |
| 索引 | 每张租户表必须有 `@@index([tenantId, id])`；业务唯一索引必须带 `deletedAt` 维度 |
| 外键 | 业务表**不建外键指向 Tenant**（将来平台侧平移成控制面服务时外键会挡路） |

### 3.3 多文件 schema 组合机制

Prisma 6 支持 `schema` 指向目录。但 **Prisma 不能从 `node_modules` include**，所以采用「同步 + 校验」而不是「引用」：

```
apps/api/prisma/schema/
├─ 00-base/            ← @taizan/prisma-base 同步过来，文件头写明「框架托管，勿改」
│  ├─ 00-datasource.prisma   （generator + datasource，唯一一处）
│  └─ 01..08-*.prisma
└─ 10-business/        ← 项目自己的片段，例如 10-goods.prisma
```

- `pnpm taizan:schema-sync` —— 从 `@taizan/prisma-base` 拷贝 `00-base/` 并写入 `base.lock.json`（每个文件的 sha256 + 包版本）。
- `base-schema-integrity.spec.ts` —— 比对现有 `00-base/` 与 lock 的 sha256，**改了框架片段就变红**；升级框架 = 升版本 + 重跑 sync + review diff。
- 生成器产出的项目里 `prisma:migrate` 前置依赖 `schema-sync`，避免「装了新版包但 schema 没更新」。

### 4.9 统一响应与错误码（定死一个）

响应包 `{ code: number; message: string; data: T }`，`code=0` 成功；业务错误 **HTTP 200 + 业务码**（`BizException`），传输层错误（401/403/404/429/500）走 `HttpException` 并同样包成信封。逃生口 `@RawResponse()`（支付回调、文件下载）——**不是硬编码路径前缀**。

**错误码：7 位 `DD HHH NN`** = 域段 2 位 + HTTP 语义 3 位 + 序号 2 位。

| 域段 | 含义 | 域段 | 含义 |
|---|---|---|---|
| 10 | 通用/参数 | 15 | 配额与功能开关 |
| 11 | 认证与会话 | 16 | 支付 |
| 12 | 租户与隔离 | 17 | 三方集成 |
| 13 | RBAC | 18 | 队列与任务 |
| 14 | 计费与套餐 | 19 | 平台运营 |
| **20–89** | **业务项目自定义** | 90 | 系统内部 |

前端判定规则只有一行：`httpSemantic(code) = Math.floor((code % 100000) / 100)`，`401` → 清态跳登录，`403` → 只提示不登出。示例：`1140100` 未登录、`1340300` 无权限（RBAC；11 段刻意只留 401 的认证与会话，「无权限」全仓只有这一个码）、`1240300` 跨租户越权、`1440301` 套餐到期只读（后台弹「去续费」）、`1440302` C 端打烊、`1540301` 配额超限、`1540302` 套餐未含此功能。**这几个码必须分开**——合成一个笼统的「无权限」，商家只会来问客服。

**唯一真源是 `@taizan/contracts` 的 `ErrorCode` 内置表**（含 16 支付 / 17 三方集成 / 18 队列 / 19 平台运营各段）；`@taizan/nest-rbac`、`@taizan/payment-core`、`@taizan/wechat-open` 里的表只是它的别名，不再各自算一遍码值。传输层兜底码是唯一的例外：由 `transportErrorCode(status)` 现算（`10` 段 + 状态码 + `00`，如 `404` → `1040400`），按规则而不是枚举存在。全表见 `docs/ERROR-CODES.md`（由 `pnpm docs:error-codes` 生成，CI `--check` 守着）。

```bash
cd demo && pnpm install
```

`e2e:acceptance` 断言 **9 条，不写一行业务代码**：① 平台超管登录 → ② 建租户 + 选套餐 → ③ 商家店主登录（一号多店时先选店，不发 token）→ ④ 切换店铺（`POST /api/admin/auth/switch` 重签 token，`tenantId` 换、`accountId` 不换；框架里「店」就是 Tenant，没有独立 store 实体）→ ⑤ C 端会员登录 → ⑥ 示例 CRUD 增删改查全通 → ⑦ 租户 A 的 token 访问租户 B 的资源返回 `1240300` → ⑧ 把 `planExpireAt` 改成昨天，后台写接口返回 `1440301` 而 `/api/admin/billing` 仍可写、C 端返回 `1440302` → ⑨ 下一笔套餐订单走 Fake 支付回调，租户自动续期且 `AuditLog` 有记录。

## 7. 业务扩展机制（以 `example-goods` 贯穿）

新业务模块要做的**七件事，每件一行代码或一个文件**：

| 扩展点 | 怎么做 | 示例 |
|---|---|---|
| ① 加表 | 在 `prisma/schema/10-business/10-goods.prisma` 写片段；必须 `tenantId String` + `@@index([tenantId, id])` + `deletedAt` | `model Goods { id String @id; tenantId String; name String; priceCents Int; status GoodsStatus; deletedAt DateTime? ... }` |
| ② 注册隔离 | `src/tenancy/tenant-models.ts` 加名字 | `registry.register(['Goods', 'GoodsSku'])` |
| ③ 注册权限点 | 模块内 `goods.permissions.ts`，`definePermissions({...})`，在 `src/registry/permissions.ts` 汇总 | `'goods:list' / 'goods:write' / 'goods:delete' / 'goods:export'` |
| ④ 注册菜单 | 模块内 `goods.menus.ts`，`defineMenus([...])`，带 `permission` 与 `featureKey` | `{ key:'goods.list', componentKey:'GoodsList', permission:'goods:list', featureKey:'goods' }` |
| ⑤ 注册套餐功能项 | `src/registry/features.ts` 加 `{ key:'goods', name:'商品模块', writeOnly:true, pathPrefixes:['/api/admin/goods'] }` | 只拦写不拦读；`plan-feature.spec.ts` 拿真实 `@Controller` 前缀比对 |
| ⑥ 注册审计动作 | `src/registry/audit-actions.ts` 加常量，控制器上 `@Audit({...})` | `GOODS_DELETE = 'goods.delete'` |
| ⑦ 注册队列任务 | `goods-sync.handler.ts` 上 `@JobHandler({name:'goods.sync'})`，在 `src/registry/jobs.ts` 汇总 | 任务名带模块前缀，死信可在平台后台重放 |

前端侧只需两步：`apps/admin/src/routes/component-map.ts` 里注册 `GoodsList` 组件、页面里用 `useCrudTable({ list: api.goods.list })`。

`tools/codegen` 的 plop 模板 `pnpm gen:module goods` **一次生成以上全部七处 + 一个 rules 纯函数 + 三个 spec**，模板内置 tenantId 过滤与权限装饰器，避免手写遗漏。

## 8. 架构约束测试清单（静态断言，CI 强制）

| # | spec | 断言内容 | 守护的不变量 |
|---|---|---|---|
| 1 | `tenant-models.spec.ts` | 扫全部 `prisma/schema/**/*.prisma`：带 `tenantId` 的 model 必须在 `TENANT_MODELS`；清单里的 model 必须在 schema 里有 `tenantId`；白名单必须写理由；带「正则失效防假通过」哨兵 | 漏登记 = 静默跨租户泄漏（xiaodian 2026-08 真实事故） |
| 2 | `tenant-scope.spec.ts` | ≥25 个行为用例：四类操作全覆盖、`upsert` 三分支、`findUnique` 补 `select.tenantId`、`where` 用 `AND` 包裹后调用方无法覆盖、无上下文抛错、未识别操作抛错 | 隔离决策函数本身 |
| 3 | `raw-usage.spec.ts` | 全仓 `prisma.raw` 调用点必须落在允许清单（登录跨租户找账号 / 支付回调定位租户 / 平台模块目录），且每处必须有 `// raw-reason:` 注释 | 逃生口不被滥用 |
| 4 | `no-manual-tenant-filter.spec.ts` | 业务模块源码里禁止出现字面量 `tenantId:` 出现在 `where` 上下文（平台模块与 raw 白名单除外） | 「禁止手写 tenantId 过滤条件」 |
| 5 | `guard-default-deny.spec.ts` | 每个 `@Controller` 的每个路由方法：要么被全局守卫覆盖（默认拒绝），要么显式 `@Public()`；`@Public()` 的路由必须同时声明限流档位 | 新控制器忘写守卫的默认结果是「拒绝」 |
| 6 | `permission-registry.spec.ts` | 双向：源码里每个 `@RequirePermission('x')` 的 `x` 必须在注册表；注册表里每个 API 类权限点必须至少被一个路由或菜单引用 | 权限点漂移、死权限 |
| 7 | `menu-route-map.spec.ts` | 菜单注册表的每个 `componentKey` 必须在 `apps/admin`/`apps/platform` 的 `component-map.ts` 里有映射；每个带 `permission` 的菜单，该权限点必须存在 | 前端菜单渲染出空白页 |
| 8 | `billing-routes.spec.ts` | `ALWAYS_WRITABLE_PREFIXES` 必须与真实 `@Controller` 前缀匹配；功能开关的 `pathPrefixes` 不许盖住这三个前缀 | 「到期→只读→续不了费→永远到期」死循环 |
| 9 | `money-field.spec.ts` | 扫 schema：禁止 `Decimal`；名字含 `price/amount/fee/balance` 的数值列必须以 `Cents` 结尾并为 `Int` | 对账口径打架 |
| 10 | `enum-and-key.spec.ts` | 扫 schema：状态类列（名为 `status/type/kind`）必须是 enum；所有 `@id` 必须是 `String`；租户表必须有 `@@index([tenantId, id])`；软删表的唯一索引必须含 `deletedAt` | 主键/枚举/索引约定 |
| 11 | `credential-registry.spec.ts` | 加密列注册表 ↔ schema 的 `*Enc` 列 ↔ 轮换脚本覆盖列，三处对账；且每个 `*Enc` 列必须有配对的 `keyId` 列 | 密钥轮换漏列 = 换完密钥读不出来 |
| 12 | `cluster-safe.spec.ts` | 禁止 `setInterval` / 裸 `@Cron`（必须 `@LeaderCron`）；一次性凭据必须走 `takeOnce`；进程内 `Map` 缓存必须标注 `// process-local:` 理由 | 4 实例并发跑 cron（knowledge 线上活故障） |
| 13 | `ip-source.spec.ts` | 全仓禁止直接读 `x-forwarded-for` / `req.ip`，只能用 `resolveIps` | XFF 前几段可伪造，限流形同虚设 |
| 14 | `provision-single-path.spec.ts` | 建租户的事务只允许出现在 `@taizan/provision` 的调用点；控制器里不许再拼一遍 | 自助注册能建出手工路径建不出来的租户 |
| 15 | `base-schema-integrity.spec.ts` | `prisma/schema/00-base/**` 的 sha256 与 `base.lock.json` 一致 | 手改框架 schema 片段导致升级冲突 |
| 16 | `tenant-middleware.spec.ts` | `TenantMiddleware.forRoutes` 必须排除 `/api/public/*` 与 `/api/platform/*`，且与控制器前缀比对 | 注册时店铺还不存在，中间件失败关闭会 500 |

### knowledge `CLAUDE.md` 8 条不变量
